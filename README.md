# AI 算法及交互中心共享规划与规范

本仓库维护多个业务仓库共同参照的产品需求、架构总纲、总体规划、接口契约和开发参考。相关实现仓库据此细化设计、实施计划和验收，不各自维护另一份总纲正文。

当前入口：[机器人云端 Agent OS 产品需求与架构总纲](docs/robot-agent-os-spec.md)，版本 v2.2，Bumi 首发并面向后续机型适配。需求与验收边界以该文档为准，实际实现状态由各业务仓库的源码、测试和交付记录说明。

本仓库是公共仓库。只收录已批准公开的共享内容；个人工作记录、私人决策台账、凭据、用户数据、部署密钥及内部运行资料不放在这里。总纲中引用的部分实现仓库与内部知识库条目需要组织访问权限。

## 内容组织

| 位置 | 用途 |
| --- | --- |
| `docs/` | 产品需求、架构总纲及跨仓设计说明；当前含 Agent OS 总纲 |
| `plans/` | 后续经批准公开的总体规划与跨仓里程碑 |
| `contracts/` | 后续多仓共用的接口、协议、数据语义与兼容契约 |
| `references/` | 后续共享开发参考、约定和示例 |

后三类按实际内容需要建立目录。业务实现、部署配置和各仓自己的实施任务书继续留在对应仓库。

## 开发时读取同一版本

`main` 中的正文是当前已审定的共享规范。分支和 PR 用于讨论变更，合入 `main` 后才成为当前规范；分支与 PR 的内容同样公开。

各业务仓库的 `AGENTS.md` 应提供本仓库入口，并要求人在设计、开发和验收前，以及编码 Agent 在每个相关任务开始时，完成以下步骤：

1. 获取远端 `Noetix-AI/aic-specs` 的 `main` 提交 SHA。
2. 按这个固定 SHA 读取本 README 和本任务相关的规范正文，避免读取期间 `main` 变化而混用版本。
3. 在任务记录和 PR 中保留所依据的 SHA、规范路径和适用章节，例如 `Spec-Commit: <完整提交 SHA>`。
4. 提交 PR 前再次检查远端规范；相关内容发生变化时，读差异、评估影响，并补齐受影响的设计、实现或验证，再记录复核结果。

网页阅读可从[仓库首页](https://github.com/Noetix-AI/aic-specs)进入；需要追溯某次实现时，使用该任务记录的提交链接读取对应版本。规范在 `main` 更新后，各仓下次读取的是同一份最新正文，无需逐仓复制文件。

本仓库没有部署常驻监听或自动改写各仓工作区的机制。已经进行中的任务须在上述检查点重新读取；本地缓存须记录来源 SHA。网络或读取失败时明确报告，不把缓存内容称为已确认的最新版。

## 修改与交付

修改走分支和 PR，不直接推送 `main`。产品需求变更先由产品决策负责人确定，再更新总纲；各仓任务书随后对齐。实现设计发现冲突时，在 PR 中指出具体条目和影响，由负责人决定需求是否改变，不自行偏离总纲。

跨仓需求与规范正文在这里维护。业务仓库和知识库可保留导航及使用说明，引用本仓库当前正文或明确的历史版本。变更说明写清影响的仓库、接口及验收，不把规范更新等同于代码已完成或功能已通过验收。

纯文档变更在 PR 中说明 TDD 不适用，并核对内容差异、链接、版本与相关条目是否一致。有行为变化的代码改动遵循 [AGENTS.md](AGENTS.md) 中的中心 TDD 约定。
